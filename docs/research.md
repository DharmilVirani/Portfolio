## Market Patterns

Strong portfolios did not rely on one trick. They combined:

- Immediate identity: name, role, and point of view are visible without digging.
- Evidence over ratings: skills appear beside actual work, not as arbitrary progress bars.
- Case-study structure: the strongest work is explained through problem, decisions, contribution, and limits.
- A memorable artifact: at least one interaction or visual moment gives the visitor something to remember.
- Content scale: standout portfolios often include archives, writing, or project histories so the owner does not look like a single-page template.
- Trust signals: resume, external links, accessible structure, source notes, and clear contact paths.

## Portfolio Direction

The final site uses an editorial systems identity: warm paper, sharp cobalt accents, a technical grid language, and original project visuals. The hero is designed as an overlay composition rather than a split template. Case studies emphasize what Dharmil actually built or inspected: Rust event pipelines, a desktop medicine-record tool, a typing interaction, and a full-stack food/cart project.

Skills are presented in context:

- Rust, Redis, PostgreSQL, WebSockets, and Docker appear in the market-signal case study.
- Electron, SQLite, Excel import/export, and local workflow design appear in the veterinary drug index case study.
- HTML, CSS, JavaScript, and interaction design appear in TurboTypist.
- React, Node.js, Express, Redux, and routing appear in Foodie.

The portfolio intentionally avoids unsupported content:

- no fake testimonials;
- no invented adoption numbers, benchmark numbers, revenue, conversion, or trading returns;
- no private project source redistribution;
- no real medical, clinic, broker, or internal employer data;
- no public deployment claim until Dharmil asks for deployment.

## Content Management

Astro content collections give the project a simple CMS-like model without a hosted CMS account:

- each case study is a Markdown file;
- frontmatter is schema validated in `src/content.config.ts`;
- featured/archive ordering is controlled by metadata;
- project visuals are generated by reusable components;
- production output is static HTML/CSS/JS.

This keeps maintenance practical: Dharmil can add a project by creating one Markdown file and choosing a visual type, order, tags, role, and context.

## Verification Strategy

The portfolio is checked with:

- `npm run check` for Astro and TypeScript validation;
- `npm run build` for production static output;
- Playwright for browser workflows, no-JS fallback, reduced motion, and overflow checks;
- axe checks on representative public pages;
- screenshot capture across 1440, 390, and 320 pixel widths.

Automated accessibility checks are not a WCAG certification. They are a guardrail paired with semantic HTML, keyboard testing, and rendered inspection.
